## 一、这个项目在做什么

用**裸机**（无 RTOS、无 DMA）重写一台 RoboMaster 步兵的固件。

三条开发原则：

| 原则 | 含义 |
|---|---|
| **一次只加一个变量** | 先打通一条最细的线，再只在这条线上加宽 |
| **完成 = 看到现象** | 「写完代码」不算完成，「在车上看到预期现象」才算 |
| **每行都能说出为什么** | 说不出「这行为什么必须在这」的代码，不算自己的 |

## 二、硬件平台

### 2.1 主控

| 项 | 值 | 出处 |
|---|---|---|
| MCU | **STM32F427IIHx**（DJI A 板，UFBGA176） | `.ioc` → `Mcu.UserName` |
| 晶振 | HSE **12 MHz** | `.ioc` → `RCC.HSE_VALUE` |
| 主频 | PLLM=6 / PLLN=168 / PLLP=2 → **168 MHz** | `.ioc` |
| 总线 | HCLK 168M ／ **APB1 42M** ／ APB2 84M | `.ioc` |
### 2.2 引脚分配（全部来自 `.ioc`）

| 引脚 | 功能 | 挂什么 |
|---|---|---|
| **PD0 / PD1** | CAN1_RX / TX | 底盘 4×M3508 + 云台 YAW |
| **PB12 / PB13** | CAN2_RX / TX | 云台 PITCH（6623） |
| **PB6 / PB7** | USART1_TX / RX | DBUS 遥控（DR16 接收机） |
| **PE0 / PE1** | UART8_RX / TX | 调试串口 |
| **PG1** | GPIO_Output | 板载 LED |
| **PH6** | TIM12_CH1 | 蜂鸣器 PWM |
| PA13 / PA14 | SWDIO / SWCLK | 下载调试 |

### 2.3 总线上的设备

| 总线 | 设备 | 反馈 ID | 命令帧 ／ 槽位 |
|---|---|---|---|
| CAN1 | 4× M3508 + C620（底盘） | 0x201~0x204 | `0x200` ／ 槽位 = ID−0x201 |
| CAN1 | GM6020（云台 **YAW**） | **0x205** | `0x1FF` ／ 槽位 0 |
| CAN2 | 6623（云台 **PITCH**） | **0x206** | `0x1FF` ／ 槽位 1 |
| CAN2 | 2×3510 + M2006（预留，未接） | — | — |

> 一帧 8 字节能塞 4 个电机（每槽位 2 字节）。所以 `0x200` / `0x1FF` 是「**ID 1~4 / 5~8 的帧**」，
> 不是「某个电机的帧」。同一个 ID 落在哪个槽位，由它的反馈 ID 决定。

> ⚠️ **两条总线各自有独立的 0x200 / 0x1FF**，互不干扰。
### 2.4 外设参数

| 外设 | 参数 | 算式 ／ 出处 |
|---|---|---|
| CAN1 / CAN2 | **1 Mbps** | 42M ÷ 3 ÷ (1+10+3) = 1 Mbps（`can.c`） |
| USART1（遥控） | **100000 / 8 数据位 / 偶校验 / 1 停止位** | `usart.c` |
| UART8（调试） | 115200 / 8N1 | `usart.c` |
| TIM6（控制节拍） | PSC=83, ARR=999 | 84M ÷ 84 ÷ 1000 = **1 kHz** |
| TIM12（蜂鸣器） | PSC=83, ARR=369 | 84M ÷ 84 ÷ 370 ≈ 2.7 kHz |

### 2.5 中断优先级（数字越小越优先）

| 中断 | 抢占优先级 | 为什么 |
|---|---|---|
| **TIM6_DAC** | **4** | 控制节拍，最高 |
| USART1 / UART8 | 5 | 通讯 |
| CAN1_TX / CAN1_RX0 / CAN2_TX / CAN2_RX0 | 6 | 通讯，最低 |

> **设计意图**：**控制循环不能被通讯打断**。1 kHz 的 PID 一旦被拖慢，云台就会抖。

## 三、项目框架

### 3.1 分层（`USER/` 下四层）

```
application/   我要做什么        chassis.c  input.c
controller/    怎么算            pid.c          ← 纯算法，不知道电机是谁
device/        这电机的协议      gimbal.c  motor.c  remote.c
bsp/           怎么搬字节        bsp_can.c  bsp_uart.c  bsp_buzzer.c
```
**依赖方向（铁律）**：上层可以调下层，**下层绝不许调上层**。

```
application → controller → device → bsp → HAL
```

| 层 | 只负责 | 不应该出现 |
|---|---|---|
| `bsp` | 「发一帧 / 收一帧」 | 不该出现「0x206 是 pitch」这种知识 |
| `device` | 认协议：「0x206 是 6623 的反馈」 | 不该算 PID |
| `controller` | 纯算法 | 不该知道 CAN / 串口 |
| `application` | 决策：「底盘往哪走」 | 不该直接发 CAN 帧 |

### 3.2 全工程只有 5 个入口点

> **看代码的诀窍**：从这 5 个入口往里看，不要从文件列表往下看。

| 入口 | 在哪 | 干什么 |
|---|---|---|
| `main()` | `Core/Src/main.c` | 初始化 + 主循环（目前主循环是空的） |
| `HAL_TIM_PeriodElapsedCallback` | `main.c` | **TIM6 @1kHz**：`remote_update()` + `gimbal_run()` |
| `HAL_CAN_RxFifo0MsgPendingCallback` | `bsp_can.c` | CAN 收到帧 → 按 ID 分派给注册的回调 |
| `HAL_UARTEx_RxEventCallback` | `remote.c` | 遥控收完一帧 → 解包 |
| `HAL_UART_ErrorCallback` | `remote.c` | 串口出错 → **重新挂接收**（不写会永久收不到） |

## 四、设计思想（4 条）

### 4.1 参数进表，代码只查表

- `input.c` 的 `s_input_map[]`：角色 → {通道号, 是否翻转}
- `bsp_can.c` 的 `s_slot[]`：ID 段 → 回调函数

好处：**改配置不改逻辑**。将来加一个电机，只加一行表项。

### 4.2 回调注册，而不是 if-else 硬编码

```c
bsp_can_register(BSP_CAN_2, 0x206U, 0x206U, gimbal_pitch_rx);
```

`bsp_can.c` **不知道**「谁是云台」。是 `gimbal_init()` 主动来注册的。
好处：加新设备时 bsp 层一行都不用改。

### 4.3 只在 device 层认协议

6020 和 6623 的反馈帧格式**完全不同**（第 2~3 字节：一个是转速，一个是电流）。
这个差异被**关在 `gimbal.c` 里面**，上层和下层都不知道。

### 4.4 安全优先：掉线就断电

- 遥控掉线 → 输出 0（电机松掉），而不是保持上一个值
- `GIMBAL_RAW_TEST_ENABLE` 是**总保险丝**：改成 `0U`，云台恒发 0

## 五、阅读建议（新手上路顺序）

**不要从 `main.c` 第一行读到最后一行。** 按下面这条线读，读完一条线就理解一半。

### 5.1 建议顺序

| 步 | 文件 | 只看什么 | 读完你应该能回答 |
|---|---|---|---|
| 1 | `bsp_can.c` | `bsp_can_init` / `bsp_can_send_frame` / `bsp_can_register` | 一帧 8 字节怎么出去、怎么进来 |
| 2 | `motor.c` | `motor_rx`（解帧）+ `motor_send_current`（组帧） | **最简单的一条完整链路** |
| 3 | `gimbal.c` | 见 5.2 | 云台两个轴的完整闭环 |
| 4 | `pid.c` | `pid_calc` | 积分限幅和输出限幅干什么用 |
| 5 | `input.c` | `input_axis` | 摇杆原始值怎么变成 ±1 的意图 |
| 6 | `main.c` | 初始化顺序 + 5 个入口点 | 为什么初始化是这个顺序 |

### 5.2 `gimbal.c` 是本工程最复杂的文件，按这个顺序看

```
gimbal_yaw_rx          ← 6020 的帧怎么解（RM 标准格式）
gimbal_pitch_rx        ← 6623 的帧怎么解（专用格式，对比着看）
gimbal_send_pitch      ← 怎么组帧发出去（槽位 1 = 字节 2~3）
gimbal_pitch_fb        ← 原始角 0~8191 → 相对水平的偏差
gimbal_pitch_control   ← 角度环（PID + 方向 + 限幅）
gimbal_run             ← 1 kHz 总入口
```

### 5.3 每读一个函数，问自己 3 个问题

1. **谁调用它？** —— Keil 里 `Shift+F12` 查引用（只有 1 个引用 = 定义自己，说明**它没被调用**）
2. **它的输入从哪来、输出到哪去？**
3. **如果删掉它，会发生什么？**

> ⚠️ 一个真实教训：`remote_update()` 曾经只有 1 个调用者，而那个调用者被注释掉了 →
> 遥控「永远不在线」，但 `g_rc_frames` 还在涨，**看起来像正常**。
> **「函数有定义」不等于「它会执行」。**

## 八、踩坑清单（现象 → 根因）

| 现象 | 根因 | 关键点 |
|---|---|---|
| 遥控**永远收不到** | 没写 `HAL_UART_ErrorCallback` | 一次 ORE 溢出就永久停摆 |
| 云台纹丝不动，但 `g_rc_frames` 在涨 | `remote_update()` 的唯一调用者被注释了 | 函数「有定义」不等于「会执行」 |
| 云台被顶到最高处、力气很大 | PID **方向反了** → 正反馈 | 判据：**正输出必须让反馈量增大** |
| 误差锁死在 −89、不归零 | **积分饱和**（`KI × INT_LIM` 只有 200） | 顶住重力要 912 的力 |
| Watch 里看不到某个变量 | 它是文件级 `static` | 去掉 `static`，或改用模块限定名 |
| `implicit declaration` 警告 | 忘了 `#include` | **必须当错误看**（C99 猜原型，浮点参数走错寄存器） |
| 改完代码没反应 | **只编译没下载** | 先看 `Program Size` 再下载 |
